Everything runs as LXC containers on Proxmox VE 9, most of them with Docker Compose stacks inside. I use it to learn infrastructure by running services I depend on. Credentials and addresses are left out of this page on purpose.

## How a request gets in

```
Internet
   |
Router: forwards 80 and 443
   |
Reverse proxy container
   Caddy (TLS)
   CrowdSec
   AppSec WAF
   |
The service's container
```

Caddy gets its Let's Encrypt certificates through the Cloudflare DNS-01 challenge. Every public request goes through CrowdSec first, which bans known bad addresses and the ones that misbehave in my logs, then through its AppSec WAF, which blocks exploit requests inline, and only after that is it proxied to the service. A dynamic DNS updater keeps the DNS records pointed at my home connection.

Web UIs that are only for me sit behind one wildcard hostname. Its certificate also comes from DNS-01, so those names never show up in public certificate logs, and the proxy closes any connection that doesn't come from a private address.

## Security

- SSH is key-only everywhere, one key per device, and not reachable from outside the LAN. Root can't log in over SSH in any container
- TOTP two-factor on the Proxmox web UI
- Containers are unprivileged by default
- Secrets live in `.env` files readable only by their owner, and configs read them by name
- Web traffic from the internet reaches only the proxy. Every other web service sits behind it

## Storage and backups

- The data pool is ZFS RAIDZ1 on three 4 TB enterprise drives, scrubbed monthly. I've replaced failing disks by resilvering
- I bought the drives used. Before a disk joins the pool I compare its SMART data with Seagate's FARM log and run a long self-test. That check caught two drives that were sold as one model but were older drives from another maker, relabeled
- I turned off the drives' aggressive head parking with openSeaChest, on the drives themselves, so the setting survives reinstalls
- Every container is backed up nightly with vzdump in snapshot mode (zstd), keeping 3 daily, 2 weekly and 1 monthly copy. Every run sends an email, so a missing email means the job didn't run
- The boot SSD failed once and took three containers with it. I reinstalled Proxmox on a new NVMe and rebuilt the services from my own runbooks. I set up the backups after that

## Docs as runbooks

Every container has a Markdown runbook in my Obsidian vault, created from one template: specs, a services table, maintenance commands, setup steps, and known issues written as problem, cause, fix. Steps shared by all containers live in one base document that the others embed, so a fix there reaches every runbook. The index table is generated from each runbook's properties.
## This website

The pages are static, generated by Hugo. There's no JavaScript, and the styling is one CSS file and one font file. Caddy serves them from a Docker container on its own unprivileged LXC, behind the same proxy, CrowdSec and WAF as everything else.

To deploy, I push to GitHub. GitHub Actions builds the image, checks the links and scans for leaked secrets, and if all of that passes it publishes the image and points a `live` branch at the commit. A systemd timer on the container checks that branch every few minutes and pulls the new image when it changes. The server only ever pulls, so GitHub holds no credentials for it and nothing has to connect inward.
